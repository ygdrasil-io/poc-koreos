# [R0.3] iOS — `wakeUp()` fonctionnel

- **Milestone** : R0
- **Statut** : ✅ Fait (PR #172)
- **Dépend de** : —
- **Modules touchés** : kadre-uikit

## Objectif
Remplacer l'`UnsupportedOperationException` lancée par `EventLoopProxy.wakeUp()` sur iOS
par un réveil thread-safe de la boucle principale via CFRunLoop ou `performSelectorOnMainThread`.
Le callback `proxyWakeUp` doit être invoqué correctement à l'issue du réveil.

## Périmètre
### API commune (kadre-core)
Pas de nouvelle signature — correction d'implémentation uniquement :
```kotlin
// EventLoopProxy
fun wakeUp()  // ne doit plus lancer d'exception sur iOS
```

### Par backend
- **kadre-uikit** : implémenter `wakeUp()` via `CFRunLoopSourceSignal` + `CFRunLoopWakeUp` (ou `performSelectorOnMainThread:withObject:waitUntilDone:`) ; appeler le callback `proxyWakeUp` depuis le thread principal
- Tous les autres backends : non concernés

## Critères d'acceptation
- [ ] `EventLoopProxy.wakeUp()` depuis un thread secondaire ne lève plus d'exception
- [ ] Le callback `proxyWakeUp` est bien appelé sur le thread principal iOS
- [ ] Test uikit : créer un proxy, appeler `wakeUp()` depuis un thread, vérifier la réception
- [ ] Dump ABI `.klib` non modifié (correction interne)

## Notes
Mécanisme préféré : source CFRunLoop (plus proche du modèle winit `EventLoopWaker`).
Alternative `performSelectorOnMainThread` acceptable si plus simple à bridger depuis Kotlin/Native.
Référence : plan R0 §R0.3 ; specs §7 known limitations iOS.
