# [R0.6] Win32 — tailles non cachées (`GetClientRect`/`GetWindowRect`)

- **Milestone** : R0
- **Statut** : À faire
- **Dépend de** : —
- **Modules touchés** : kadre-win32

## Objectif
Remplacer la lecture de taille depuis le cache interne Win32 par des appels directs à `GetClientRect`
(pour `innerSize`) et `GetWindowRect` (pour `outerSize`), afin que les valeurs soient toujours fraîches
même si le cache n'a pas encore été mis à jour.

## Périmètre
### API commune (kadre-core)
Pas de nouvelle signature — correction d'implémentation uniquement :
```kotlin
// Window
val innerSize: PhysicalSize   // via GetClientRect
val outerSize: PhysicalSize   // via GetWindowRect
```

### Par backend
- **kadre-win32** : remplacer les lectures cache par `GetClientRect(hwnd)` / `GetWindowRect(hwnd)` dans les accesseurs `innerSize`/`outerSize` ; le cache peut rester pour d'autres usages internes mais ne doit plus être la source de vérité pour ces propriétés
- Tous les autres backends : non concernés

## Critères d'acceptation
- [ ] `innerSize` retourne la taille réelle après un redimensionnement sans attendre le prochain `WM_SIZE`
- [ ] `outerSize` inclut les décorations natives (barre de titre, bordures)
- [ ] Tests win32 : redimensionner via SetWindowPos puis lire `innerSize`/`outerSize` immédiatement
- [ ] Dump ABI non modifié

## Notes
Risque mineur de performance si `innerSize`/`outerSize` sont appelés en boucle serrée (appels Win32 synchrones).
Si un profilage montre un problème, documenter et reconsidérer — mais la correction est prioritaire sur l'optimisation.
Référence : plan R0 §R0.6.
