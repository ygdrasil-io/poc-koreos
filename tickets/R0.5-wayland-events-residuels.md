# [R0.5] Wayland — événements résiduels

- **Milestone** : R0
- **Statut** : À faire
- **Dépend de** : —
- **Modules touchés** : kadre-wayland

## Objectif
Compléter le dispatch d'événements Wayland manquants dans la boucle d'événements existante :
`ScaleFactorChanged` (via `wl_output.scale` ou preferred-scale), `Focused` (via `wl_keyboard.enter/leave`),
et `Touch` (via `wl_touch`).

## Périmètre
### API commune (kadre-core)
Pas de nouvelle signature — les trois événements sont déjà déclarés dans `WindowEvent` :
```kotlin
data class ScaleFactorChanged(val scaleFactor: Double, val innerSize: PhysicalSize) : WindowEvent()
data class Focused(val focused: Boolean) : WindowEvent()
// Touch events déjà dans WindowEvent (à confirmer — sinon ajouter)
```

### Par backend
- **kadre-wayland** :
  - `ScaleFactorChanged` : s'abonner à `wl_output.scale` (protocole wl 3+) et `wp_fractional_scale_v1` (preferred scale) ; émettre lors du changement
  - `Focused` : mapper `wl_keyboard.enter` → `Focused(true)`, `wl_keyboard.leave` → `Focused(false)`
  - `Touch` : mapper les événements `wl_touch` (`down/up/motion/cancel/frame`) vers les touch events Kadre
- Tous les autres backends : non concernés

## Critères d'acceptation
- [ ] `ScaleFactorChanged` émis lors d'un changement de scale Wayland (test weston)
- [ ] `Focused(true/false)` émis sur entrée/sortie du focus clavier
- [ ] Touch events émis lors de contact tactile (test weston ou mock `wl_touch`)
- [ ] Tests wayland dans la matrice CI (weston headless)
- [ ] Dump ABI non modifié

## Notes
Pour `preferred_scale` (Wayland fractional-scale v1), vérifier la disponibilité du protocole en runtime et fallback sur `wl_output.scale` entier.
Référence : plan R0 §R0.5.
