# [R0.4] X11 — `scaleFactor` réel (Xft.dpi / RANDR)

- **Milestone** : R0
- **Statut** : ✅ Fait (PR #173)
- **Dépend de** : —
- **Modules touchés** : kadre-x11

## Objectif
Remplacer la valeur codée en dur `1.0` de `scaleFactor` sur X11 par une lecture dynamique.
Lire `Xft.dpi` depuis les ressources X ou interroger RANDR pour le DPI physique du moniteur,
puis émettre `ScaleFactorChanged` quand la valeur change (hotplug, changement de moniteur).

## Périmètre
### API commune (kadre-core)
Pas de nouvelle signature — correction d'implémentation uniquement :
```kotlin
// WindowEvent déjà déclaré :
data class ScaleFactorChanged(val scaleFactor: Double, val innerSize: PhysicalSize) : WindowEvent()
```

### Par backend
- **kadre-x11** : lire `Xft.dpi` via `XGetDefault(display, "Xft", "dpi")` ; fallback sur RANDR (`XRRGetScreenResources` + calcul mm→dpi) ; émettre `ScaleFactorChanged` sur `RRNotify`
- Tous les autres backends : non concernés

## Critères d'acceptation
- [ ] `scaleFactor` retourne une valeur > 1.0 sur un écran HiDPI X11 (ex. 1.5 ou 2.0)
- [ ] `ScaleFactorChanged` est émis lors d'un hotplug moniteur (test Xvfb / randr mock)
- [ ] Fallback raisonnable (1.0) si ni `Xft.dpi` ni RANDR ne sont disponibles
- [ ] Tests x11 dans la matrice CI (Xvfb)
- [ ] Dump ABI non modifié

## Notes
Priorité de lecture recommandée : `Xft.dpi` > RANDR DPI physique > 1.0.
Attention aux environnements de CI headless (Xvfb n'a pas de RANDR par défaut — utiliser `Xvfb +extension RANDR` ou mocker).
Référence : plan R0 §R0.4.
