# [R0.2] Web — tailles et `scaleFactor` réels

- **Milestone** : R0
- **Statut** : À faire
- **Dépend de** : —
- **Modules touchés** : kadre-web-common, kadre-js, kadre-wasm

## Objectif
Remplacer les valeurs codées en dur dans `WebWindow` par des lectures dynamiques du DOM.
`innerSize`/`outerSize` doivent utiliser `ResizeObserver` ; `scaleFactor` doit lire `window.devicePixelRatio` et émettre `ScaleFactorChanged` lors d'un zoom navigateur.
Le pont Wasm a déjà l'observateur câblé — il faut le brancher à `WebWindow` et au côté JS.

## Périmètre
### API commune (kadre-core)
Pas de nouvelle signature — correction d'implémentation uniquement :
```kotlin
// WindowEvent déjà déclaré :
data class ScaleFactorChanged(val scaleFactor: Double, val innerSize: PhysicalSize) : WindowEvent()
```

### Par backend
- **kadre-web-common** : brancher `ResizeObserver` sur `WebWindow.innerSize`/`outerSize` ; lire `devicePixelRatio` pour `scaleFactor` ; émettre `ScaleFactorChanged` quand `devicePixelRatio` change (listener `matchMedia`)
- **kadre-js** : wiring JS → `WebWindow` via l'interface existante
- **kadre-wasm** : wiring Wasm → `WebWindow` (l'observateur est déjà là — raccorder)
- Tous les autres backends : non concernés

## Critères d'acceptation
- [ ] `innerSize` retourne la taille CSS réelle de l'élément canvas (pas une constante)
- [ ] `scaleFactor` retourne `devicePixelRatio` (ex. 2.0 sur écran Retina/HiDPI)
- [ ] Un zoom navigateur (Ctrl+/−) déclenche `ScaleFactorChanged` avec la bonne valeur
- [ ] Tests JS et Wasm (puppeteer / karma) vérifiant les trois points ci-dessus
- [ ] Dump ABI non modifié (aucune surface publique nouvelle)

## Notes
Pas de breaking change API. Risque : la fréquence d'émission de `ScaleFactorChanged` lors du zoom — prévoir un debounce si nécessaire.
Référence : plan R0 §R0.2.
