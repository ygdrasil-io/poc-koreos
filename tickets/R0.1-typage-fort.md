# [R0.1] Typage fort — supprimer tous les `Any`

- **Milestone** : R0
- **Statut** : À faire
- **Dépend de** : —
- **Modules touchés** : kadre-core, kadre-appkit, kadre-uikit, kadre-android, kadre-web-common, kadre-js, kadre-wasm, kadre-win32, kadre-x11, kadre-wayland

## Objectif
Remplacer chaque `Any` dans la surface publique par des types scellés concrets.
`windowEvent(event: Any)` et `deviceEvent(event: Any)` deviennent typés ; `rawWindowHandle` et `rawDisplayHandle` passent de `Any` à `RawWindowHandle` / `RawDisplayHandle`.
Aucune nouvelle fonctionnalité — correction pure de la signature déclarée.

## Périmètre
### API commune (kadre-core)
Les types scellés `WindowEvent`, `DeviceEvent`, `RawWindowHandle`, `RawDisplayHandle`
**existent déjà** dans `kadre-core` (`Events.kt`, `RawHandles.kt`). R0.1 ne crée pas de
type : il **retyppe les signatures** qui exposent encore `Any`.
```kotlin
// ApplicationHandler — Any -> types scellés (garder le param eventLoop)
fun windowEvent(eventLoop: ActiveEventLoop, windowId: WindowId, event: WindowEvent)
fun deviceEvent(eventLoop: ActiveEventLoop, deviceId: DeviceId, event: DeviceEvent)

// Window — Any -> types scellés
val rawWindowHandle: RawWindowHandle
val rawDisplayHandle: RawDisplayHandle
```
Variantes existantes (rappel, ne pas renommer) : `RawWindowHandle.{AppKit, UiKit, Android,
Win32, Xlib, Wayland, Web}` ; `RawDisplayHandle.{AppKit, UiKit, Android, Win32, Web, Xlib, Wayland}`.

### Par backend
Chaque backend construit **déjà** la bonne variante ; le travail est de **supprimer le
type `Any`** des propriétés/override et les casts devenus inutiles, puis de passer un
`WindowEvent`/`DeviceEvent` typé aux sites de dispatch.
- **kadre-appkit** : `RawWindowHandle.AppKit(nsView, nsWindow, nsLayer)` / `RawDisplayHandle.AppKit`
- **kadre-uikit** : `RawWindowHandle.UiKit(uiView, uiViewController)` / `RawDisplayHandle.UiKit`
- **kadre-android** : `RawWindowHandle.Android(surface)` / `RawDisplayHandle.Android`
- **kadre-win32** : `RawWindowHandle.Win32(hwnd, hinstance)` / `RawDisplayHandle.Win32(hinstance)`
- **kadre-x11** : `RawWindowHandle.Xlib(window, display)` / `RawDisplayHandle.Xlib(display)`
- **kadre-wayland** : `RawWindowHandle.Wayland(surface, display)` / `RawDisplayHandle.Wayland(display)`
- **kadre-web-common** : `RawWindowHandle.Web(canvasElementId)` / `RawDisplayHandle.Web`
- **kadre-js** / **kadre-wasm** : délèguent à web-common

## Critères d'acceptation
- [ ] Zéro `Any` dans la surface publique de kadre-core après le changement
- [ ] Chacun des 9 backends compile avec les nouveaux types
- [ ] Les `when` exhaustifs sur `WindowEvent` et `DeviceEvent` compilent sans `else`
- [ ] Tests par backend : dispatch d'un événement de chaque branche scellée
- [ ] Dump ABI régénéré (android `.api` / ios `.klib`)
- [ ] wgpu4k notifié / coordonné avant la sortie (breaking change)

## Notes
⚠️ **Breaking change** : le consommateur wgpu4k utilise un `when` exhaustif sur les handles et les événements — coordonner la sortie de version avec l'équipe wgpu4k (cf. plan §4).
Référence : specs §3.1.5, §3.4 ; plan R0 exit criteria.
