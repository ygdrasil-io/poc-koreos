## Deadlock révélé par la gate

Le watchdog a révélé un blocage intermittent dans le scénario natif existant
`publicDesktopApplicationOpensFromAWorkerAndObservesNativeInput` au commit
`9b373083`. La pile JVM capturée montre le cycle exact :

```text
Worker : RuntimeLock détenu → finishOpenDispatchLocked → onSurfaceReady
         → showWindow → Win32UiCommandQueue.invoke → attend UI
UI     : ShowWindow → WndProc → acceptSurfaceStimulus → attend ce RuntimeLock
```

Le worker de test a été arrêté après capture ; ce run est un échec, pas une
qualification. Une régression portable avec dispatcher contrôlé prépare le peer
sur l'UI avant la fin d'admission sur worker : elle constatait l'affichage sur le
mauvais thread. L'ensemble activation/affichage/observation est désormais posté
à l'UI ; le callback de commit retourne avant tout appel natif. Cette correction
fait partie de la passe finale, validée par la suite complète et le watchdog, sans deuxième revue indépendante.

Les bindings générés ont été examinés sélectivement avec SDK/entrées épinglés ;
le code manuscrit a été revu entièrement. Les 125 fonctions se régénèrent à
l'identique. La revue ne remplace pas une nouvelle dérivation indépendante de
chaque ABI ni les essais matériels/IME.

## Deferred minors

- `Win32TextUiWork.run` : si le callback interne `onFailure` fourni lève lui-même
  une exception, la finalisation et sa lease peuvent rester pendantes. Le reporter
  runtime normal est protégé ; cette robustesse exceptionnelle est différée et
  n'a pas été incluse dans la passe des Important.

tactile/stylet/gomme et changement réel de moniteur/DPI restent à recevoir

pas l'activation au premier contact d'une fenêtre en arrière-plan. Android/UIKit
et autres environnements natifs absents restent à leur CI. Publication distante,
pin timestampé et même gate sans Maven local restent requis avant de clore la
phase. Inertia, PTP2 et raw input appartiennent aux phases suivantes.

Les lectures de paquets restent dans le message natif valide, conformément aux
contrats Microsoft de [GetPointerInfo](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getpointerinfo)
et [GetPointerFrameTouchInfoHistory](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getpointerframetouchinfohistory).
