# iOS/tvOS Phase 8 — Displays, signaux système, devices et gamepads — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fill the common managers with honest iOS/tvOS observations: a real `DisplayPort` inventory (UIScreen-based on iOS, explicit `HostViewport` on tvOS), a memory-pressure relay for the non-graduated `UIApplicationDidReceiveMemoryWarningNotification` (documented single-level mapping), `InputDevicePort` + `GamepadPort` over the public GameController primitives, and `Unsupported(RawInputAccess)` kept — each domain decided separately with exact absence states.

**Architecture:** Four independent domains, one contract. Ports implement the runtime interfaces verified unchanged since c062f261 (`DisplayPort`, `GamepadPort`, `InputDevicePort` — runtime untouched between c062f261 and 23b52e69) and plug into `RuntimeSessionComponents` at the attach seam, mirroring the **Android AND-008 precedent** (seam interfaces hide SDK types; full re-enumeration per fire; sync publication at install; events outside the lock) and the **AppKit precedents** (process-wide memory-pressure source with claims + `LifecycleCapabilities` at construction; GameController broker with lifecycle fanout). Threading = main-thread notifications observed block-based, state under `RuntimeLock`, deliveries outside it. No `kadre/runtime` changes.

**Tech Stack:** Kotlin Multiplatform 2.4.20, UIKit klib (`UIScreen`, `UIApplicationDidReceiveMemoryWarningNotification` — present both platforms), GameController klib (`GCController`, `GCExtendedGamepad`, `GCMicroGamepad`, `GCDeviceHaptics` — present iOS+tvOS; `GCControllerProfileExtended` is a Swift name, 0 klib hits), XcodeGen driver, Gradle contract validator + simulator gate.

3. **Siri Remote as full gamepad** — a micro-profile controller entering `GamepadPort`, or micro buttons entering a 17-button descriptor. Test: Task 4 + tvOS driver scenario.
4. **Double ownership** — the same physical keyboard/gamepad delivered twice (phase-5 keyboard binding vs InputDevicePort), or an effect surviving its port/scene teardown. Tests: Task 4/5 ownership + Task 6 scenario.
5. **Phantom device IDs** — a disconnected device keeping its old key on reconnect (runtime demands "nouvel ID après disparition terminale"), or key collisions across domains. Test: Task 4 key-assignment kernel.
